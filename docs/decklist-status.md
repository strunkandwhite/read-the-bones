## The submission inbox — `data/decklists.txt`

Hand-maintained section. Not regenerated by `pnpm decklists:integrity`.

`data/decklists.txt` is an **inbox, not an archive**: it holds sealeddeck.tech URLs that
have not yet been ingested. As of 2026-08-09 it is **empty** — every URL it held has
been accounted for.

Provenance now lives in `deck_hashes.sealeddeck_id`, so "which submission produced this
seat's deck?" is a query rather than a grep:

```sql
SELECT draft_id, seat, sealeddeck_id FROM deck_hashes WHERE sealeddeck_id IS NOT NULL;
```

### Known data-quality items, not blocking

- **7 orphaned `deck_hashes` rows** for opted-out seats (`blightning:10`,
  `innistrad-dark-ascension:2`, `ledger-shredder:5`, `maelstrom-pulse:3`, `pyrogoyf:4`,
  `rabbit-battery:8`, `ravnica:4`). Their `deck_cards` were removed by redaction but the
  hash row predates the fix that now deletes both together, so `deck_hashes` holds 215
  rows against 208 stored decklists. Harmless; safe to delete.
- **`rabbit-battery:3`** carries a sentinel `hash = ''` from its malformed submission,
  which forces re-evaluation on the next run rather than short-circuiting. Intended.
- **Split cards have duplicate `cards` rows** — a short-name row and a full-name row with
  different `card_id`s, for `Claim // Fame`, `Commit // Memory`, `Life // Death` and
  `Unholy Annex // Ritual Chamber`. `deck_cards` references the short-name ids in 13 rows
  across 12 seats; `pick_events` only ever uses the full names. Matching is unaffected
  (`cardNameKey` folds them), but any future join of `deck_cards` to `pick_events` **by
  `card_id`** would be wrong for those seats.
